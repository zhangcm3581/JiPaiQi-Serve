# 模拟客户端与服务端验收

不需要先完成APK，也可以验证服务端收发、状态流转和数据一致性。测试用合法生成的两副牌替代识别输入，使用真实WebSocket发送协议消息；截图识别和新局特征由后续手机端联调验收。

## 一条命令生成HTML报告

在项目根目录执行：

```sh
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python scripts/test_report.py
```

输出：

- `reports/test-report.html`：包含CSS和交互脚本的静态报告，双击可离线打开；支持搜索、分类、展开证据和打印。
- `reports/test-report.json`、`reports/test-report.xml`：本次结果与JUnit数据。
- `reports/traces/`：每个真实网络场景发送、接收的JSON消息以及隔离服务日志。

脚本自动创建临时SQLite数据库，在随机本机端口启动独立Uvicorn服务，用模拟客户端建立真实TCP/WebSocket连接。不会连接当前8768服务，不会清空或写入管理后台已有租户，不需要部署权限。测试结束关闭测试进程。报告和测试消息已被Git忽略；原始消息是合成测试牌，不来自手机截图。

全量运行通常约1～2分钟，其中包含真实45秒空闲连接回收和真实10秒牌局超时。默认180秒牌局边界还使用可控时钟测试，避免每次等待3分钟。任何断言失败、服务异常、静态检查失败或测试期间源码变化，报告会标记未通过，脚本以非零状态退出。

## 场景覆盖

| 分类 | 验证内容 |
|---|---|
| 收发与计算 | 7端乱序、最后一端延迟、每份13张、两副牌91+13守恒、七端与后台结果一致 |
| 缺席与超时 | 只开启6端、不收齐就结束、首份起算、无结束消息自动关闭 |
| 去重与校验 | 同ID重放、重排同手牌、内容冲突、双副同牌可重复、第三副拒绝、12/14张、非法花色点数 |
| 版本 | 未绑定上传、旧牌换版本、新局事件复用、漏过多局、手动推进、最大版本耗尽 |
| 租户隔离 | 相同版本/设备ID/请求ID在不同租户独立，禁止消息身份与连接身份不符 |
| 并发 | 同端20次并发重传、7端同时结束、12轮最后一份与结束竞争、8租户56端并发 |
| 连接与恢复 | 重连重放ack、已锁定结果补推、同ID替换、第8设备限制、15秒心跳/45秒空闲回收 |
| 持久化 | 6份后正常停止或强杀测试服务，重新启动后保留版本、手牌、截止时间、原ack |
| 连续状态 | 20轮固定种子随机发牌与上传顺序、历史不被新局修改、所有测试数据库完整性与外键检查 |
| 协议边界 | HTTP/WS超大版本、二进制帧、超64KiB帧、错误后可重连或继续心跳 |
| 部署更新 | 临时Git和SQLite，模拟systemd/pip，覆盖成功、回退、本地修改与并发更新锁 |

真实网络用例位于`tests/test_scenarios.py`，使用`tests/wire_support.py`的独立连接和牌组对照；报告模板、CSS和JS分别位于`scripts/report/`，生成时合并成一个离线HTML。

每项报告记录操作步骤、预期、实际断言结果、收发数量及关键证据。用例数量来自当次JUnit结果，不是手写“全部通过”。报告还保存运行与测试源码的SHA256指纹，标识实际验收的工作区内容。

只运行真实网络场景：

```sh
.venv/bin/python -m pytest tests/test_scenarios.py -q
```

## 在现有后台观看收发过程

服务运行后，选取专用测试租户。例如：

```sh
.venv/bin/python scripts/simulate.py --url http://127.0.0.1:8768 --tenant 900002 --delay-last 15 --hold-seconds 30 --end
```

打开`/live?tenant=900002`：先看到6/7等待，15秒后收到第7份并填入结果，保持30秒后结束，进入下一版本。历史页面可查看该轮的7份数据和结果。命令会创建或使用此专用模拟租户，留下真实数据库记录；当前轮次未结束时脚本会拒绝再次开始，不覆盖已存在的牌局。

这与全量验收隔离服务不同：`simulate.py`明确连接指定服务器，适合人工观看；`test_report.py`使用临时服务，适合反复回归。

## 本次发现及适用范围

2026-09-09边界测试发现：版本查询入口未校验整数范围，超大版本可触发SQLite整数溢出。修复前8项查询边界回归失败，基线保存在本机`reports/before-fixes.xml`；修复在`Store.round()`统一校验版本。HTTP返回422，WS返回`INVALID_MESSAGE`且后续心跳仍可使用。具体复测结果见当次HTML报告。

通过测试不代表不存在任何bug。尚未覆盖APK截图识别、真实模拟器和牌桌、Ubuntu/Nginx/WSS外网链路、长期负载或磁盘故障。尤其没有共同游戏局号时，服务端不能证明截图属于同一局；新局与结束必须由客户端可靠识别。单端误报结束仍会按当前协议提前关闭；只有join没有有效手牌时不启动牌局超时，这些是当前规则而非测试可消除的风险。
